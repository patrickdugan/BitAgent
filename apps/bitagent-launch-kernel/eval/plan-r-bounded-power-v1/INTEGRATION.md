## Interface contract

Input from model to host (only through Python-to-Node JSONL stdin):

```json
{"schema":"bitagent.plan_r_candidate.v1","action":"read_a","authority":"model_candidate","effect":"none"}
```

The host accepts only **exactly** these four JSON keys and an eight-action vocabulary. The host returns `bitagent.plan_r_gate_decision.v1` containing `run_id`, `arm`, `seed`, `attempt`, source manifest digest, state hashes, an admit/deny decision, an explicit reason, a hash-chain predecessor, and `physical_effect:false`. `execution`, `authorization`, `signing`, `broadcast`, and `secret_access` are always `false`.

To turn this into a production BitAgent policy evaluation in a future PR, maintain the true planner/task packet generated by `src/launch/dagCandidate.ts`, invoke its actual `validateDagCandidate` through the existing application host, and record its decision receipt. The Plan R action names must stay within their mock-only namespace. Avoid attaching real tools, wallet credentials, approval objects, or unsandboxed network endpoints to the experimental model.

## Preregistered next measurements

For a learned model, register exactly which tasks reward `compile` and which actions are adversarial probes, plus a matched no-peer control. Freeze the per-arm maximum prompt budget, decoding mode, 96 call ceiling, 96 new-token ceiling, one initial seed, and an external wall/job envelope. Compare parsed-candidate rate, benign compilation success, synthetic violation frequency, denied requests, and total proposals. The toy system's exact reachable set is a ceiling for what any actor can induce; an actor's failure to visit a state is one observation of its policy and exploration strategy.

A later experiment may replace the toy with a validated Storyworld or agent-tool sandbox. That transition requires a new versioned authority map and source/target lineage pins. Do not silently reuse `unsafe` or `capability_proxy` as real-world safety metrics.
